# Intel G1.5 — Stage E experiment verdicts (2026-11-08)

**Plan:** `docs/plans/2026-11-08-intel-g1.5-opencl-flavored-spirv.md`.
**Node:** Arc B390 (Xe3), L0 1.32, clang 22, spirv-tools.
**Harnesses:** `/tmp/g15/` (experiment-only; the committed gates arrive with
Stage F). Probe: `l0launch.c` — `zeModuleCreate(IL_SPIRV)` → kernel enumeration
→ `zeKernelCreate` → host-USM → args `(ptr, i64)` → group size 32 →
immediate-list launch → host sync → read `state[0]`.

## E1 — OpenCL-flavored IL: acceptance + ABI + entry — PASS

`__kernel void briev_kernel(__global long* state, long n)` writes
`state[0] = n + 7` from lane 0; compiled
`clang --target=spirv64 -x cl -cl-std=CL3.0` (spirv-val clean).

```
module=0 OK
kernel_count=1
  kernel[0]=briev_kernel
kernel=0 OK
args=0
groupsize=0
append=0
sync=0
state0=107
```

**Verdict:** IGC accepts OpenCL-flavored IL; the kernel argument ABI
`(ptr state, i64 n)`, the entry lookup, and the immediate-list launch all work
on PTL.

## E1b — subgroup reduce in OpenCL flavor — PASS

`sub_group_reduce_add(get_global_id(0))` over one 32-lane subgroup:

```
state0=496            # 0+1+...+31
```

**Verdict:** `OpGroupNonUniformIAdd` is accepted and executed through the IL
path. The §12 fold lanes (Int; `approx` float) are viable on the L0 lane.

## E2 — Vulkan flavor with a legal entry name — FAIL (flavor is the blocker)

Real Briev-emitted blob for `g0_elem`'s `selfadd` (1444 bytes; `OpCapability
Shader` + `GLSL450`), entry string byte-patched `main` → `brvk` (spirv-val
clean). IGC result:

```
module=0 OK
kernel_count=0
EMPTY_KERNEL_SET
```

**Verdict:** the empty-kernel-set blocker is the **module flavor**, not the
entry name alone. Stage F (OpenCL projection) is required.

## E3 — `OpExecutionMode LocalSize` on a Kernel entry — PASS

Assembled `OpExecutionMode %briev_kernel LocalSize 32 1 1` into the E1b
module (`spirv-as --target-env spv1.4`, `spirv-val` clean): IGC accepts it and
execution is unchanged (`state0=496`). The fold lanes' LocalSize requirement
survives the OpenCL projection.

## Finding: `main` is not a legal OpenCL kernel name

`clang -x cl` refuses to compile `__kernel void main(...)`:
`error: kernel cannot be called 'main'`. The OpenCL-flavored projection must
use another entry name (convention: `briev_kernel`); the L0/OpenCL drivers
look that name up. (This is also consistent with NEO's
`CL_INVALID_KERNEL_NAME` on our `main` entry.)

## Consequences for Stage F

1. Flavor projection: capabilities Kernel (not Shader), OpenCL memory model,
   `OpEntryPoint Kernel %fn "briev_kernel"`, state pointer as a kernel arg
   (CrossWorkgroup), builtin variables for ids.
2. Entry-name convention `briev_kernel`; drivers try it (fallback `main` for
   back-compat).
3. Dual-image descriptor (Vulkan blob + OpenCL blob) with both-side ABI pins;
   drivers pick their flavor and fall through when absent.
4. E1c (coopmat via IL) remains open; it decides G3 on L0 but does not block
   the projection.
