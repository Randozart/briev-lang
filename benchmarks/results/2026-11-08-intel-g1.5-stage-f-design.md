# Intel G1.5 Stage F — OpenCL projection design constraints (2026-11-08)

Experiment-first probe of the SPIR-V surface an OpenCL-flavored image needs,
before touching the emitter. Toolchain: clang 23.1.3 (`--target=spirv64`),
spirv-as/spirv-dis/spirv-val (SPIR-V 1.4). Device gates still run on PTL via
`benchmarks/intel_ptl/`.

## Blueprint (clang OpenCL C, validated)

Source: `__kernel void k(__global long* s) { size_t i = get_global_id(0);
s[0] = (long)i; }`

Module head and state/ABI shape:

```
OpCapability Kernel
OpCapability Addresses
OpMemoryModel Physical64 OpenCL
OpEntryPoint Kernel %k "k" %__spirv_BuiltInGlobalInvocationId
...
%_ptr_CrossWorkgroup_ulong = OpTypePointer CrossWorkgroup %ulong
%5 = OpTypeFunction %void %_ptr_CrossWorkgroup_ulong
%k = OpFunction %void None %5
%7 = OpFunctionParameter %_ptr_CrossWorkgroup_ulong
```

- Kernel arguments are **function parameters** (the L0 driver's
  `zeKernelSetArgumentValue(kernel, 0, ptr)` / `(kernel, 1, u64)` shape).
- Builtins stay decorated Input-storage variables and ARE listed in the
  `OpEntryPoint` interface (`%__spirv_BuiltInGlobalInvocationId`).
- The entry point name can be any legal identifier; `main` is refused by
  clang's OpenCL frontend, so the projection uses `briev_kernel` (Stage E).

## Constraint 1 — Logical addressing is invalid with the OpenCL model

`spirv-val` on the clang module with the memory model rewritten to
`OpMemoryModel Logical OpenCL`:

```
error: In Logical addressing, variables can only allocate a pointer to the
StorageBuffer or Workgroup storage classes
  %6 = OpVariable %_ptr_Function__ptr_CrossWorkgroup_uchar Function
```

⇒ The OpenCL flavor must use `Physical64` (32-bit targets: `Physical32`) and
`CrossWorkgroup` for the state pointer.

## Constraint 2 — `Block` / `Offset` require the Shader capability

Adding `OpDecorate %struct Block` (or only `OpMemberDecorate ... Offset`) to
the Kernel-capability module:

```
error: Operand 2 of Decorate requires one of these capabilities: Shader
error: Operand 3 of MemberDecorate requires one of these capabilities: Shader
```

⇒ The OpenCL image CANNOT express the current state struct's explicit
offsets with member decorations. Clang's own OpenCL output hosts the struct
with **no** Block/Offset decorations and addresses through physical pointer
arithmetic (`OpInBoundsPtrAccessChain` on a byte pointer, then bitcast).

## Consequence for the emitter

Briev's state buffer has a single host ABI layout (`projection_offsets`:
name-sorted fields, vec4-eligible arrays 16-aligned, scalars packed, buffer
reuse aliases). That layout is what the runtime staging buffer and the
Vulkan image share. Two options:

1. **Physical offsets (chosen).** OpenCL kernel argument 0 is
   `ptr CrossWorkgroup u8`; field access lowers to
   `OpInBoundsPtrAccessChain` with the field's byte offset, bitcast to the
   field pointer type, then normal element indexing. One staging layout for
   both images; no second descriptor.
2. Natural-layout struct. Rejected: SPIR-V natural layout differs from the
   packed/16-aligned CPU layout, so the host staging buffer would need a
   second per-image layout and size mirror in `briev_rt`.

## Scope boundary for the first projection slice

- Non-GEMM, non-image kernels only (`g0_elem`, `g0_sum`, `g0_minmax`,
  `g0_fsum_approx`, `g0_fsum_exact`). Word/tiled/coopmat GEMM stays
  Vulkan-only until G3 (E1c decides cooperative-matrix-on-IL); image
  bindings stay Vulkan-only (UniformConstant descriptors are not kernel
  args in the current plan).
- Entry `briev_kernel`; `OpExecutionMode LocalSize` unchanged (Stage E3).

## Next implementation steps

1. `SpirvFlavor { Vulkan, OpenCL }` in `SpirvBuilder` (capability set,
   `Physical64 OpenCL`, entry `Kernel`, storage class `CrossWorkgroup`).
2. OpenCL state ABI: `ptr CrossWorkgroup u8` parameter + byte-offset
   `PtrAccessChain` lowering for field loads/stores (replaces
   `AccessChain`-member + `Offset` decorations on this flavor only).
3. Kernel function signature: `void(briev_state*, u64 n)`; builtins in the
   entry interface; `briev_kernel` name.
4. Descriptor dual image (append OpenCL SPIR-V + size), L0/OpenCL drivers
   prefer it, Vulkan unchanged; ABI pins in the same commit.
5. Promote `levelzero` (and `opencl` where the lane works) to REQUIRED in
   `g0.sh`; record per-lane correctness.
