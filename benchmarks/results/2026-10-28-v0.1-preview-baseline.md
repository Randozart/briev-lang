## I11 real browser/server gate

Reached the full functional flow: unique account registration, login,
catalogue, five seeded ratings, live optimistic rating, accepted event,
fresh recommendations before the row lock releases, and correct rendered
recommendation list.

**PASS after fix:** `maxLongTask=0 ms`, `xhrSends=0`, animation frames
continue, one recommendation event, no follow-up GET.

Root cause: defn emission inherited the previous transaction's `txn_name`.
Every `term` in `client_movie_title` therefore ran `emit_web_flush_batch`,
flushing all 32 bound fields per recursive title lookup — about 32,000 full
DOM effect passes during one rating click. Defn entry now clears `txn_name`;
the app IR fell from 246 flush calls to 53.

Also fixed: keyed `b-each` reconciliation moved every row with
`appendChild` on every effect pass. It now advances a cursor and calls
`insertBefore` only for out-of-order rows.

The runner is now checked in and passes from a clean app checkout:

```bash
python3 benchmarks/recommender_responsiveness/run_i11_browser.py \
  --compiler /path/to/brievc --output /tmp/recommender-i11-browser-run
```

It records source/artifact hashes, build/server logs, `summary.json`, and stops
only the server it starts. Latest run: exit 0, `maxLongTaskMs=0`.

## Compiler defect found by I11 — FIXED in working tree

`server = server_step(server,100)` assigned a returned `ServerState` to a
top-level **unpacked instance**. Codegen emitted the `server_step` call but no
column stores, so the next node firing read the pre-call snapshot. Registration
inserted the account, the worker replied `registered`, and the HTTP response
was never sent.

Fix: the assignment path now calls `emit_instance_seed_from_value` for
top-level pooled/unpacked instances. Regression:
`top_level_instance_assignment_seeds_columns`.

After the fix, registration returns:

```http
HTTP/1.1 200 OK
{"v":1,"type":"registered"}
```

## Browser responsiveness defect found by I11 — FIXED in working tree

Defn `term` statements inherited the previous transaction's `txn_name` on the
shared function state, so `emit_web_flush_batch` treated every recursive
`client_movie_title` return as a full state commit. One rating click produced
about 32,000 full DOM effect passes. Clearing `txn_name` at defn entry removes
the flush; keyed-list reconciliation also stopped moving unchanged rows.
Regression: `webstack_stateful_defn_after_txn_does_not_flush`.

## Phase 2 interpreter parity — closed

- Callable txns, small ws codec, dynamic-list parity, and the 7000-byte
  `ws_encode` growth path all pass.
- Root cause: reactor `foreach` handled only `Product`, silently skipping
  integer ranges. `ws_encode`'s source fill was a no-op; at `i=4096` the
  zero-filled buffer made `4096+4096` look like a zero-length string at the
  heap base and `Load#` saw address 0. Foreach now delegates to the
  interpreter evaluator.
- `ws_encode_growth_interpreter` is un-ignored; reactor range regression added.

## Phase 4 performance — regression found and fixed

- Full runtime suite completes with output parity before and after the fix.
- `compare_baseline.sh ws_frame`: RED at 3.85x, caused by `retain_enum_return`
  copying every enum image on return. Removed the redundant copy; ratio is now
  1.00x and `enum_local_return` still passes.
- Post-fix C-relative suite: `ws_frame` reached **0.30x C** before a
  correctness follow-up; `deep_recursion` is a tie; all outputs MATCH.
- Correctness follow-up: removing the enum-return copy outright crashed
  `server_protocol_gate`. Current retention is limited to local identifiers and
  passes every cargo/app gate, but `ws_frame` is a known **2.48x** locked-baseline
  regression. A by-value/ownership-proved enum ABI is required before the
  preview tag.
- Other sampled locked-baseline A/Bs: `arena_bump` 1.00x,
  `deep_recursion` 1.00x.
- Remaining C gaps are quality targets, not baseline regressions:
  `arena_bump` 4.67x C, `spsc_ring` 1.98x C, `sweep_mid` 1.34x C.
