## I11 real browser/server gate

Reached the full functional flow: unique account registration, login,
catalogue, five seeded ratings, live optimistic rating, accepted event,
fresh recommendations before the row lock releases, and correct rendered
recommendation list.

**Open:** responsiveness assertion fails. The renderer reports a 3.5 s
`longtask` during the blocked-persistence window (`maxLongTask=3534 ms`;
gate requires `<50 ms`). `xhrSends=0` and animation frames continue, so this
is not a synchronous-fetch failure. A launch with
`--no-wasm-lazy-compilation` did not change the result.

Renderer profile attribution (1 ms sampling): the dominant hits are DOM
`appendChild` and `app.mjs:applyItem`/`querySelector`, not wasm compilation or
network. The final DOM is only 208 elements (12 catalogue cards, 5
recommendation cards), so this is repeated view-patch churn rather than a large
render. Next step: count state flushes/view effects during the optimistic save
and batch the patch instead of re-applying it per field write.

The I11 Python runner is absent from the checkout; the gate was run directly:

```bash
node tests/fixtures/recommender/browser_live_server.mjs \
  target/recommender-i11-web http://127.0.0.1:18110
```

## Compiler defect found by I11 — FIXED in working tree

`server = server_step(server,100)` assigned a returned `ServerState` to a
top-level **unpacked instance**. Codegen emitted the `server_step` call but no
column stores, so the next node firing read the pre-call snapshot. Registration
inserted the account, the worker replied `registered`, and the HTTP response
was never sent.

Fix: the assignment path now calls `emit_instance_seed_from_value` for
top-level pooled/unpacked instances. Regression:
`top_level_instance_assignment_seeds_columns`.

After the fix, registration returns:

```http
HTTP/1.1 200 OK
{"v":1,"type":"registered"}
```
