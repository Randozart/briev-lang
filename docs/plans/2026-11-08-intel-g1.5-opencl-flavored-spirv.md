# Intel G1.5 — OpenCL-flavored SPIR-V projection (unblocks Level Zero / NEO OpenCL)

**2026-11-08.** Status: ACTIVE. **Thread:** XPU (this plan is the only pure-XPU
item currently open; the general workstream is separately queued).
**Provenance:** `docs/architecture/intel-dispatch.md` G1 verdict (2026-11-06):
the Level Zero driver is built and wired, but IGC compiles Briev's
**Vulkan-flavored** SPIR-V to an **empty kernel set** (`zeModuleGetKernelNames`
→ 0; `zeKernelCreate("main")` → `0x78000011`). NEO's OpenCL/IL path shows the
same disease (`CL_INVALID_KERNEL_NAME`, empty names). Vulkan (ANV) remains the
working Intel lane (G0: six gates PASS on PTL).

**Goal:** project an **OpenCL-flavored** SPIR-V image from the SAME frontend
plan (capabilities/entry/memory model/kernel args), so Level Zero (and likely
NEO OpenCL) expose and execute Briev kernels. This is the "vendor projection"
of D3, not a second emitter design.

## Why flavor changes everything

| Aspect | Vulkan flavor (current) | OpenCL flavor (needed for IGC IL) |
|---|---|---|
| Capability | `Shader` | `Kernel` |
| Memory model | GLSL450 / Vulkan memory model | OpenCL |
| Entry | `OpEntryPoint GLCompute %main "main"` | `OpEntryPoint Kernel %main "main"` |
| State buffer | SSBO global + descriptor set binding | **kernel argument** (pointer param) |
| Workgroup size | `OpExecutionMode LocalSize` | `OpExecutionMode LocalSize` (verify) |
| Builtins | decorated variables | decorated variables / OpenCL builtin linkage |

The L0 driver's launch ABI was deliberately built for this shape:
`zeKernelSetArgumentValue(kernel, 0, ptr, &staging)` and `(kernel, 1, u64, &n)`
(`lib/runtime/briev_dev_levelzero.c`).

## Stage E — experiments on PTL (BEFORE any emitter work)

Experiment-first, per the house protocol. Each experiment writes its own small
harness under `benchmarks/intel_ptl/` (or `tests/` when it becomes a gate) and
records verdicts in the results file.

### E1 — acceptance + ABI + entry

- Hand-write an OpenCL-C kernel mirroring our elementwise shape:
  `__kernel void main(__global long* state, long n)` writing a sentinel to
  `state[0]` for `get_global_id(0) == 0`.
- `clang --target=spirv64 -x cl -cl-std=CL3.0 -c` → `spirv-val` →
  `zeModuleCreate(ZE_MODULE_FORMAT_IL_SPIRV)` → `zeKernelCreate("main")` →
  host-USM alloc → set args `(ptr, i64)` → group size (32,1,1) →
  `zeCommandListAppendLaunchKernel` → host sync → read sentinel.
- **Acceptance:** module + kernel create succeed; sentinel correct on PTL.

### E1b — subgroup ops in OpenCL flavor (decides the idiom lanes on L0/NEO)

- `sub_group_reduce_add(get_global_id(0))` over one 32-lane subgroup → write
  `496` to `state[0]`.
- **Acceptance:** kernel runs; result correct; `spirv-dis` shows
  `OpGroupNonUniformIAdd`; IGC accepts it (no fallback).
- This decides whether the §12 fold lanes (Int + `approx` float) can run on
  the L0/NEO lanes at all.

### E1c — cooperative matrix via IL (decides G3 on L0)

- Does IGC accept `SPV_KHR_cooperative_matrix` (or the CL Intel matrix
  extensions) through `ZE_MODULE_FORMAT_IL_SPIRV`? Vulkan (ANV) is verified;
  L0 is not.
- **Acceptance (either way, recorded):** if IGC accepts and executes a
  one-workgroup coopmat kernel, G3 targets L0; otherwise XMX stays on Vulkan
  and L0 serves the tiled/int lanes.

**Gate outcome:** E1 + E1b pass → Stage F. E1 fails → re-scope (Vulkan-only
Intel lane; the L0 driver retires or takes a NATIVE-binary path — both out of
this plan). E1c is recorded independently, not a Stage-F blocker.

**Stage E RESULTS (2026-11-08): E1 PASS, E1b PASS, E2 FAIL (flavor confirmed
as the blocker).** Full verdicts:
`benchmarks/results/2026-11-08-intel-g1.5-stage-e.md`. Additional finding:
`main` is not a legal OpenCL kernel name (clang refuses to compile it), so the
projection's entry is `briev_kernel` and the L0/OpenCL drivers look it up.
E2: a Vulkan-flavored blob with a patched legal entry name still yields an
empty kernel set — the flavor projection is required, not just a rename.

## Stage F — emitter projection (only after E gates pass)

1. **Flavor parameter** in the SPIR-V builder/lower (`Vulkan | OpenCL`):
   capability set, memory model, addressing model, entry execution model,
   and the state-pointer-as-kernel-arg path (no descriptor set/reorder).
   One frontend plan; the flavor is a projection (D3).
2. **LocalSize**: keep `OpExecutionMode LocalSize` (verified by E1); the
   driver's `local_x` parse already reads it.
3. **Builtin linkage**: decorate `GlobalInvocationId`/`LocalInvocationId`
   variables (E1/E1b pattern) instead of the Vulkan-by-value entry interface.
4. **Descriptor/ABI (dual image)**: append an OpenCL-flavored SPIR-V image +
   size to `BrievKernelDesc` (append-only, both-side pins:
   `test_kernel_desc_abi_layout` + `accel_rt::desc_abi` in one commit).
   Existing producers zero-fill; drivers pick their flavor and fall through
   when absent (Vulkan keeps the current image).
5. **Emitters**: the `.bv` blob path (`llvm/kernel.rs::collect_accel_kernels`)
   and the `.abv` path (`spirv/mod.rs`) emit both flavors from the same
   plan. No frontend decision changes.
6. **Drivers**: `briev_dev_levelzero` and `briev_dev_opencl` prefer the
   OpenCL image; keep the empty-kernel-set diagnostics (they become the
   fall-through signal).
7. **Gates**: `g0.sh` promotes `levelzero` (and `opencl` if E1 shows NEO
   works) to REQUIRED rungs; Vulkan stays required. Record per-lane
   correctness (all six fixtures) in the results file.

## Stage G — follow-ons

- **G2**: device-USM working set + resident 2-D path on L0 (D4/D5).
- **G3**: coopmat negotiation for L0 if E1c passes; else Vulkan-only XMX.
- **G5**: performance vs the OpenVINO collector baselines (Workstream B),
  with the collector as the timing source.

## Risks

- IGC may accept the module but still expose no kernels for some constructs
  (nested foreach, subgroup variants, i64 atomics) — E1b/E1c probe these.
- OpenCL memory-model requirements (e.g., barrier/`OpControlBarrier` scope)
  differ from Vulkan; the fold lanes use subgroup ops with no barriers, but
  the general lane's SLM/shared usage needs a barrier audit.
- Dual-image descriptor is an ABI change: both-side pins mandatory (house rule).
- Emitting both flavors doubles blob size; acceptable (blobs are per-kernel,
  not per-launch).

## Non-goals

- No OpenCL-C **source** emission path (the doctrine wants one SPIR-V plan;
  clang is used only inside the experiments to produce reference modules).
- No relaxation of Vulkan as the required Intel lane until an alternative is
  proven better for a benchmark.
