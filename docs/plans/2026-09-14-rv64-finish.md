## 0. Goal

Close every designed-but-deferred item from the rv64 capability arc, plus
prove the architecture is not a coincidence by landing a second board
(ARM Cortex-M QEMU MPS2-AN385). Eight items, five phases, each with a
measurable gate.

## 2. Phases

### Phase 1 — Emitter correctness

**Goal**: defns with contract brackets compile as linear callables, not

**Files touched**:
- `src/backend/llvm/emit_toplevel.rs` — `emit_callable_txn()`: detect

**Gate**: the kernel demo compiles with brackets restored on the

### Phase 2 — `:=` derivation

**Goal**: `:=` blocks on defns validate the programmer's mental model
at compile time. Given input X, expect Y. Each example generates a
runnable test. The three-tier epistemics (proven / asserted / unknown)
are wired.

**Design** (from Addendum B.3, corrected framing):

```briev
defn add(x: Int, y: Int) -> Int
    := { 0, 0 => 0; 1, 2 => 3; -1, 1 => 0; }
    := { x, 0 => x; 0, y => y; }
;
// body: x + y
```

- Syntax: `:= { <pattern> => <expected>; }` (one-liner or multi-line)
- Comptime-evaluable bodies: examples checked at compile time
  (mismatches = compile errors)
- Machine-opaque bodies (`Asm#`): examples compile into the test gate
  (verified where the body lives)
- Totality warnings: if examples don't cover all arms, warn
- Dead-arm candidates: if an arm is never matched by any example, note it

**Files touched**:
- `src/lexer/token.rs` — `Token::Derive` (the `:=` token)
- `src/parser/mod.rs` — parse `:= { ... }` blocks on defns
- `src/ast/mod.rs` — `Derivation` AST node (patterns + expected expressions)
- `src/typechecker/mod.rs` — typecheck derivation examples (input types
  match defn signature, expected type matches return type)
- `src/backend/llvm/emit_toplevel.rs` — emit derivation examples as
  test functions (or inline checks at comptime)
- `tests/` — derivation tests (comptime pass, comptime fail, machine-opaque
  gate, retroactive kernel validation)

**Gate**: a one-line derivation on `trap_frame_base()` catches the
`ret i64 0` bug at compile time (the retroactive validation story from
Addendum B.3). 2199 + new derivation tests green.

### Phase 3 — rv64 ergonomics

**Goal**: the kernel demo uses resume scheduling (task pc + registers
preserved across traps, not restarted from top). Canned `_start` lives
in board data, not hardcoded in the emitter.

#### 3a. Resume scheduling

The current kernel uses restart scheduling: each trap re-runs the task
body from the top. Resume scheduling preserves the interrupted pc +
full register set in the task's context area, so `mret` returns to
exactly where the task was interrupted.

**Files touched**:
- `examples/kernel_rv64.b.bv` — the scheduler saves head snapshots
  (`ctx_save`) and restores them (`ctx_restore`); the task body runs
  once, not per-trap
- `docs/architecture/machine-entry.md` — update "restart vs resume"
  section with the shipped pattern

**Gate**: the kernel demo output changes from `BABABABABABA` (restart)
to `BABA` (resume — each task prints once, preempted mid-print, resumed
later). New golden output, new gate test.

#### 3b. Canned `_start` extraction

The canned `_start` fallback (sp ← _stack_top, .bss zero, jump to
reset) lives in `emit_toplevel.rs` as Rust code. Extract it to board
data: the board's `addresses.dbvl` or a new `boot.dbvl` file carries
the sequence, and the emitter reads it.

**Files touched**:
- `lib/boards/qemu-virt-rv64/boot.dbvl` — canned start sequence as data
- `src/backend/llvm/emit_toplevel.rs` — read canned start from board data
  instead of hardcoded Rust strings

**Gate**: a program without `bootstrap node` still compiles and runs
(the fallback path). 2199 tests green.

### Phase 4 — Language-wide cleanup

**Goal**: the `la $0, trap_service` template wart is deleted. The
reactor's park policy is correct for address-wired eligibility.

#### 4a. Link-time symbol values

The current `Asm#` template in `wire_trap_vector` references
`la $0, trap_service` — a symbol the compiler doesn't know at parse
time. With link-time symbol values, the compiler emits the symbol as
an LLVM global and the linker resolves it.

**Files touched**:
- `src/backend/llvm/emit_expr.rs` — `Asm#` template expansion:
  recognize symbol references, emit as LLVM global references
- `src/backend/llvm/emit_toplevel.rs` — symbol table emission
- `examples/kernel_rv64.b.bv` — `wire_trap_vector` uses the new syntax
  (no more `la $0`)

**Gate**: the kernel demo compiles and runs unchanged. The template
wart is gone from the source.

#### 4b. Frontier-driven equilibrium / wake_sets

The reactor parks at `wfi` when no state-sequenced or vectored
eligibility exists. Address-wired eligibility (polled devices) must
not be slept through.

**Files touched**:
- `src/analysis/` — `AnalysisResults.wake_sets` computation
- `src/backend/llvm/loop_engine/ssa.rs` — equilibrium park policy:
  wfi only when wake_sets confirms no address-wired readers

**Gate**: a program with address-wired polling does not sleep through
eligibility. The equilibrium wfi-vs-addresses BUGS.md entry is closed.

### Phase 5 — ARM Cortex-M QEMU (second architecture proof)

**Goal**: a second board runs — hello world and timer ticks on QEMU
MPS2-AN385 (ARM Cortex-M3). Proves the architecture is data, not
coincidence: the same `bootstrap node` / `@ vector` / mechanism
inference pattern works on a completely different ISA.

**Files touched**:
- `config/targets.dbvl` — new entry: `target.thumbv7m: 32; 4.0; 0; arm_cortex_m;`
  (links to the existing `arm_cortex_m` ISR mechanism)
- `lib/boards/mps2-an385/addresses.dbvl` — UART0 `0x40004000`, SYSTICK
  `0xE000E010`, NVIC `0xE000E100`, RAM `0x20000000`
- `lib/boards/mps2-an385/interrupts.dbvl` — `timer_irq: 15;` (SysTick),
  `uart_irq: 3;` (UART0)
- `lib/boards/mps2-an385/registers.dbvl` — PL011 UART register map
- `lib/targets/qemu-mps2-an385.ld` — linker script (RAM at 0x20000000,
  512 KB, entry at 0x20000000)
- `examples/hello_arm.b.bv` — hello world via UART write
- `examples/timer_arm.b.bv` — SysTick-driven tick count
- `tests/bare/qemu-arm-hello.sh` — golden gate (output: `Hello, ARM!`)
- `tests/bare/qemu-arm-timer.sh` — golden gate (output: `123456789012`)

**Gate**: `qemu-system-arm -M mps2-an385 -nographic` runs both examples,
golden output matches. The mechanism inference path (board → target →
ISR mechanism → scaffold) is exercised on a second ISA.

**Prerequisite**: `qemu-system-arm` installed (check with
`qemu-system-arm --version`).
