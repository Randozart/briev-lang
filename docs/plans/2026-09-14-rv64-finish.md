prove the architecture is not a coincidence by landing a second board

### Phase 2 — `:=` derivation

**Goal**: `:=` blocks on defns validate the programmer's mental model
at compile time. Given input X, expect Y. Each example generates a
runnable test. The three-tier epistemics (proven / asserted / unknown)
are wired.

**Design** (from Addendum B.3, corrected framing):

```briev
defn add(x: Int, y: Int) -> Int
    := { 0, 0 => 0; 1, 2 => 3; -1, 1 => 0; }
    := { x, 0 => x; 0, y => y; }
;
// body: x + y
```

- Syntax: `:= { <pattern> => <expected>; }` (one-liner or multi-line)
- Comptime-evaluable bodies: examples checked at compile time
  (mismatches = compile errors)
- Machine-opaque bodies (`Asm#`): examples compile into the test gate
  (verified where the body lives)
- Totality warnings: if examples don't cover all arms, warn
- Dead-arm candidates: if an arm is never matched by any example, note it

**Files touched**:
- `src/lexer/token.rs` — `Token::Derive` (the `:=` token)
- `src/parser/mod.rs` — parse `:= { ... }` blocks on defns
- `src/ast/mod.rs` — `Derivation` AST node (patterns + expected expressions)
- `src/typechecker/mod.rs` — typecheck derivation examples (input types
  match defn signature, expected type matches return type)
- `src/backend/llvm/emit_toplevel.rs` — emit derivation examples as
  test functions (or inline checks at comptime)
- `tests/` — derivation tests (comptime pass, comptime fail, machine-opaque
  gate, retroactive kernel validation)

**Gate**: a one-line derivation on `trap_frame_base()` catches the
`ret i64 0` bug at compile time (the retroactive validation story from
Addendum B.3). 2199 + new derivation tests green.

### Phase 3 — rv64 ergonomics

**Goal**: the kernel demo uses resume scheduling (task pc + registers
preserved across traps, not restarted from top). Canned `_start` lives
in board data, not hardcoded in the emitter.

#### 3a. Resume scheduling

The current kernel uses restart scheduling: each trap re-runs the task
body from the top. Resume scheduling preserves the interrupted pc +
full register set in the task's context area, so `mret` returns to
exactly where the task was interrupted.

**Files touched**:
- `examples/kernel_rv64.b.bv` — the scheduler saves head snapshots
  (`ctx_save`) and restores them (`ctx_restore`); the task body runs
  once, not per-trap
- `docs/architecture/machine-entry.md` — update "restart vs resume"
  section with the shipped pattern

**Gate**: the kernel demo output changes from `BABABABABABA` (restart)
to `BABA` (resume — each task prints once, preempted mid-print, resumed
later). New golden output, new gate test.

#### 3b. Canned `_start` extraction

The canned `_start` fallback (sp ← _stack_top, .bss zero, jump to
reset) lives in `emit_toplevel.rs` as Rust code. Extract it to board
data: the board's `addresses.dbvl` or a new `boot.dbvl` file carries
the sequence, and the emitter reads it.

**Files touched**:
- `lib/boards/qemu-virt-rv64/boot.dbvl` — canned start sequence as data
- `src/backend/llvm/emit_toplevel.rs` — read canned start from board data
  instead of hardcoded Rust strings

**Gate**: a program without `bootstrap node` still compiles and runs
(the fallback path). 2199 tests green.

### Phase 4 — Language-wide cleanup

**Goal**: the `la $0, trap_service` template wart is deleted. The
reactor's park policy is correct for address-wired eligibility.

#### 4a. Link-time symbol values

The current `Asm#` template in `wire_trap_vector` references
`la $0, trap_service` — a symbol the compiler doesn't know at parse
time. With link-time symbol values, the compiler emits the symbol as
an LLVM global and the linker resolves it.

**Files touched**:
- `src/backend/llvm/emit_expr.rs` — `Asm#` template expansion:
  recognize symbol references, emit as LLVM global references
- `src/backend/llvm/emit_toplevel.rs` — symbol table emission
- `examples/kernel_rv64.b.bv` — `wire_trap_vector` uses the new syntax
  (no more `la $0`)

**Gate**: the kernel demo compiles and runs unchanged. The template
wart is gone from the source.

#### 4b. Frontier-driven equilibrium / wake_sets

The reactor parks at `wfi` when no state-sequenced or vectored
eligibility exists. Address-wired eligibility (polled devices) must
not be slept through.

**Files touched**:
- `src/analysis/` — `AnalysisResults.wake_sets` computation
- `src/backend/llvm/loop_engine/ssa.rs` — equilibrium park policy:
  wfi only when wake_sets confirms no address-wired readers

**Gate**: a program with address-wired polling does not sleep through
eligibility. The equilibrium wfi-vs-addresses BUGS.md entry is closed.

## 5. Addendum (2026-09-14) — Phase 5 SHIPPED, Phase 3a deferred

Status at session close, current commit:

- **Phase 1 (emitter correctness)** — shipped (`c98b7189`): defn+contract
  convergence fix + void-match fix. Gates: `BABABABABABA`, `1234…`, 2199
  tests.
- **Phase 2 (`:=` derivation)** — shipped (`c1a263b5`); pre-existing
  implementation verified end-to-end.
- **Phase 3a (resume scheduling)** — **DEFERRED**. Needs a `loop`/infinite
  iteration construct in the language: resume scheduling requires task
  bodies that keep making progress across preemptions (the current tasks
  park in `1: j 1b`, so restart == resume in observable behaviour). The
  asm-loop approximation produces burst output (`BBBB…`), not the gated
  alternating pattern. Revisit with a loop keyword; the scheduler already
  preserves the full context (the `ctx_save`/`ctx_restore` mechanism is
  present in the design).
- **Phase 3b (canned `_start` extraction)** — skipped (refactor only, no
  behavioural value; revisit if the emitter's hardcoded `_start` grows).
- **Phase 5 (ARM Cortex-M QEMU)** — **SHIPPED**. `Hello, ARM!` and
  SysTick `1234567890…` on QEMU MPS2-AN385 (Cortex-M3). Proves the
  bootstrap / `@ vector` / mechanism-inference pattern is data, not
  coincidence. Discoveries encoded in this plan's era:
  1. **MPS2 UART0 is a CMSDK APB UART, not PL011** — writes to DATA
     (`0x40004000`) are dropped until CTRL bit 0 (TXEN) is set.
  2. **ARM needs compiler-rt with the AEABI register ABI** —
     `__aeabi_ldivmod` et al. return quotient/remainder in r0–r3, which
     C struct-return cannot express (AAPCS sret). The shims
     (`compiler_rt_arm.{c,S}`) call shift-subtract C cores; the
     core-call convention (n in r2:r3, d on the stack as a full 8-byte
     slot, r1 free) was derived from the compiled core, not assumed.
  3. **Two real compiler bugs found and fixed** (regression tests added):
     - Asm# missing earlyclobber: LLVM aliased an input with the output
       when a template wrote `$0` before reading `$1` (`str $0,[$1]`
       became `str r2,[r2]`). Fix: `=&r` constraint (intrinsics.rs).
     - VolatileStore# narrowing: compared Briev metadata via
       `resolve_arg_bytes`, which under-reports the abstract Int on
       32-bit targets → invalid `zext i64 to i32`. Fix: compare the
       emitted LLVM type widths (intrinsics.rs).
  4. **Bare-metal `.data` must be copied by the board startup** — Briev
     globals (e.g. `briev_begin_boot`) live in .data; QEMU zeroes RAM, so
     the flag read 0 and boot was skipped. `startup.S` now copies .data
     from its load address and zeroes .bss.
  5. **`Default_Handler` is weak in board data** — the compiler emits its
     strong spin-loop only when ISR handlers exist; the board provides a
     weak definition for handler-less programs.

Gates at close: rv64 kernel + timer PASS, arm hello + timer PASS, 2201
tests green.

## 6. Addendum 2 (2026-09-14) — Phase 4b SHIPPED

- **Phase 4b (equilibrium vs address-wired)** — **SHIPPED**. The
  address-wired form `node n @ *<ptr>` parses as a reactor-pass Transaction
  (SPEC §13.2 addresses namespace), and the equilibrium park in
  `emit_ssa_main`'s `.end` spins (no `wfi`) whenever an address-wired node
  exists — an external frontier must re-read every pass, never be slept
  through. Two parser fixes: `parse_postfix` gained an `allow_index` gate
  (the contract brackets after `@ *expr` were being eaten as an array
  index), and the node `@` path classifies `*` as address-wired vs
  vectored. Verified end-to-end on QEMU MPS2-AN385:
  `examples/addr_wired.b.bv` polls SysTick VAL with NO interrupt and prints
  `012345678901234567890123` — the reactor spins. Regression tests:
  `test_address_wired_node_spins_not_parks`,
  `test_address_wired_node_parses_as_reactive_txn`; the wfi-park test
  (`test_embedded_equilibrium_parks_in_wfi`) still passes. BUGS.md
  equilibrium entry closed. The full writer×reader `wake_sets` closure
  remains a refinement; the no-sleep correctness property ships.
- **Phase 4a (link-time symbol values)** — **SUPERSEDED**. The `=symbol`
  reference inside a raw `Asm#` template is the DISCLOSED mechanism, not a
  wart: this era's two-ISA proof re-validated it on both ISAs (rv64
  `la $0, trap_service`, ARM `ldr $0, =systick` / `=_stack_top` /
  `=_data_init`). Per Rule 3 (disclose special treatment), removing it
  would HIDE the mechanism behind ordinary-looking syntax.
