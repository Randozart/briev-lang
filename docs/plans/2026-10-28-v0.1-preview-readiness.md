# Briev v0.1.0-preview readiness

**Date:** 2026-10-28
**Status:** ACTIVE — baseline recorded; I11 functional flow passes, responsiveness open
**Scope:** Tier 1 x86_64 Linux native + wasm32 browser; compiler, stdlib, runtime,
and the external recommender app.
**Release target:** `v0.1.0-preview` (then `v0.1.0` after Phases 3–4)
**Parent plan:** `docs/plans/2026-10-25-stability-v0.1.md`

This plan is the execution checklist for declaring Briev ready for its first
preview. It does not add language features. Every unchecked item must be green,
explicitly quarantined with a removal condition, or declared out of scope by
the owner before the tag.

## Phase 1 — Gate integrity and quarantines

**Goal:** make the default gates trustworthy.

- [ ] `cargo test --all` green as a blocking gate.
- [ ] `cargo test --lib`, `cargo test --bin brievc`, and
  `cargo test --test daily_use_smoke` green.
- [ ] The ignored/quarantined lane still executes non-blockingly.
- [ ] Resolve or keep quarantined with a removal condition:
  - C-driven Node/Python bridge round-trips;
  - CLI entry-command hangs;
  - any new failure found by this run.
- [ ] Malformed-input fuzz/proptest smoke has no panic.
- [ ] Conformance sweep green under `deny`.
- [ ] Contract census 0/0.
- [ ] IR determinism quick gate green; full gate before the tag.
- [ ] CI workflow runs the same commands as the local release gate.

**Exit:** a red default gate is a release blocker, not a local surprise.

## Phase 2 — Interpreter/backend parity

**Goal:** close the remaining Rule-5 divergence before preview.

- [ ] Interpreter executes callable Briev txns.
- [ ] Interpreter supports raw-address → String.
- [ ] Large `ws_encode` works in the reactor interpreter path.
- [ ] Compound bitwise-or residual and enum-payload match hangs closed.
- [ ] Differential gate: same fixtures through interpreter and compiled backend,

## Risks and controls

| Risk | Control |
|---|---|
| Interpreter parity is larger than expected | Keep it on the critical path; do not weaken the differential gate or ship “preview” with known divergence |
| App environment unavailable | Record the blocked gate as a release blocker, not a pass; provide exact reproduction |
| Upstream compiler fork is not writable | Pin to a public commit; keep the commit list in the app doc |
| Browser flakiness | Deterministic fixtures; rerun under the same geometry; record hashes |
| Performance noise | Interleave baseline/candidate runs; require an A/B cause |
| Scope creep from GPU/embedded | Feature freeze; experimental work is explicitly out of scope |
| Quarantine rot | Every quarantine has an owner and a removal condition in BUGS.md |

## Definition of done

The lane is done when:

1. Every Phase 0–6 checkbox is checked or has a recorded owner-approved
   exception.
2. PR #1 is ready, pinned, and backed by gate evidence.
3. `v0.1.0-preview` is tagged from a clean checkout.
4. The release notes state Tier 1 support and experimental surfaces honestly.
5. No known miscompile, interpreter divergence, panic, or unexplained
   performance regression remains hidden behind a green gate.

Maintain this file as the release ledger: update statuses in place, append dated
evidence, and do not rewrite history.
